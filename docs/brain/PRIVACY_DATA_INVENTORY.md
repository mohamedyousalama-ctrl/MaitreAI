# BRAIN Privacy Data Inventory

V1 memory is **EXPLICIT-ONLY**. The only memory categories allowed in V1 are explicit preference, confirmed address, reconfirmed safety disclosure, and structured prior confirmed order. V1 stores **no inferred memory**.

| data category | sensitivity | lawful-basis note | retention posture | deletion/correction posture |
|---|---|---|---|---|
| Phone number | Personal data; channel identifier | Required for customer conversation and order servicing. KSA PDPL notice applies. EG personal-data processing and cross-border transfer posture must be confirmed with Egyptian counsel. | Retain while the customer relationship, order support, fraud prevention, or legal accounting need remains. | Delete or anonymize on valid request unless needed for legal/accounting defense; correct canonical phone mapping on verified request. |
| Address/location | Personal data; location data | Required for delivery fulfillment. KSA notice and purpose limitation apply. EG location/cross-border posture: confirm with Egyptian counsel. | Retain confirmed delivery address only when explicitly provided and useful for future service; otherwise keep per-order evidence only for operational/legal window. | Correct confirmed address on request; delete reusable address memory when requested; retain order-bound address only where legally required. |
| Voice recording/transcript | Personal data; may include sensitive health disclosure | Voice processing requires explicit product notice. If health/allergy data appears, KSA sensitive-health-data handling requires explicit consent and retention limits; EG sensitive-data and cross-border handling are specially regulated; confirm with Egyptian counsel. | Prefer transcript/evidence minimums over raw audio; raw recordings should have short retention unless a dispute or quality review requires longer. | Delete raw voice artifacts and derived reusable memory on valid request; correct transcript-derived structured facts when customer disputes them. |
| Purchase history | Personal and commercial behavior | Order fulfillment, accounting, customer support, and explicit reorder convenience. Cross-border/accounting requirements must be confirmed for EG. | Retain confirmed orders for accounting and support; V1 memory may store only structured prior confirmed orders, not inferred habits. | Delete/anonymize non-accounting memory on request; correct mistaken order evidence with audit trail rather than silent overwrite. |

Minimize free text. | Delete reusable safety memory on request; correct structured disclosure promptly; preserve order-bound safety evidence only for required safety/legal window. |
| Conversation evidence | Personal data; may include sensitive data depending on content | Needed for customer support, dispute resolution, safety audit, and model-quality evidence. KSA purpose limitation applies; EG cross-border posture must be confirmed. | Keep minimum transcript/turn evidence needed for support, audit, and incident review; avoid retaining diagnostics in customer-visible fields. | Delete/anonymize conversation evidence where legally permissible; correct structured state derived from conversation when disputed. |
| Staff notes | Personal data; may include employee/customer annotations | Legitimate operational interest with access limitation. Health or sensitive notes inherit sensitive-data posture. EG employment/customer note handling: confirm with counsel. | Retain only operationally useful notes; separate staff-only notes from customer output and model prompts unless explicitly approved. | Delete or correct notes on valid request unless required for legal defense; log corrections with actor and reason. |

## Memory Rules

- Allowed V1 memory: explicit preference, confirmed address, reconfirmed safety disclosure, structured prior confirmed order.
- Forbidden V1 memory: inferred allergies, inferred preferences, inferred diet, inferred address, inferred spending pattern, inferred household/family profile, inferred health condition.
- Every reusable memory must carry source evidence, capture time, tenant id, and deletion/correction posture.
