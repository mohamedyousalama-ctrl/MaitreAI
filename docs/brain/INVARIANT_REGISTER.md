# BRAIN Invariant Register

These invariants govern the Kivo Transactional Dialogue Kernel (KTDK / the BRAIN). The LLM may interpret language, but code owns truth, state, decisions, side effects, and customer-visible message structure.

| # | id | statement | category | enforced by | stop-ship signal |
|---|---|---|---|---|---|
| 1 | INV-RELIABILITY-001 | Exactly one active mutable order episode may exist per conversation thread. | RELIABILITY | DB partial unique index on active `order_episodes`; episode resolver tests | More than one active episode for the same thread, or any path that can create one without hitting the unique guard. |
| 2 | INV-MONEY-001 | Money is represented only as integer minor units. | MONEY | Type branding; DB `bigint` money columns; validators; schema tests | Any prompt, type, table, or API shape that uses float, decimal math, or LLM-authored arithmetic for committed money. |
| 3 | INV-MONEY-002 | A confirmed order may commit only from an immutable, unexpired `order_quote`. | MONEY | DB quote table; confirm-to-commit validator; transaction tests | Commit proceeds when quote total, catalog, availability, quote expiry, or episode revision no longer match. |
| 4 | INV-SAFETY-001 | LLM output is untrusted until semantically validated. | SAFETY | `UntrustedUserAct` to `ValidatedUserActBatch` type boundary; validators; negative tests | Unvalidated LLM JSON/text directly mutates cart, safety state, money, tenant, order, or outbound message structure. |
| 5 | INV-TENANT-001 | No BRAIN path may read or write across tenants. | TENANT | RLS; composite tenant foreign keys; tenant-bound types; adversarial RLS tests | A forged tenant, thread, episode, quote, customer, or order id reaches data from another tenant. |
| 6 | INV-TENANT-002 | Tenant identity is derived only from verified WhatsApp number configuration. | TENANT | Webhook resolver validator; DB constraints; route tests | Customer text, LLM output, button payload, query parameter, or unverified channel metadata chooses `tenant_id`. |
| 7 | INV-TENANT-003 | No service-role client appears in ordinary BRAIN execution paths. | TENANT | Code ownership rule; static scan; route tests | Runtime BRAIN ingestion, decision, commit, or dispatch imports or constructs a service-role Supabase client. |
| 8 | INV-PRIVACY-001 | Internal, diagnostic, policy, trace, or chain-of-decision text never appears in customer output. | PRIVACY | Branded response types; renderer allow-list; snapshot tests | Any `InternalDiagnostic` or trace text is present in `CustomerResponse` or outbound messages. |
| 9 | INV-SAFETY-002 | Customer output may never authorize unsafe reassurance; the words "safe" and "آمن" are forbidden as safety authorization. | SAFETY | Canonical safety text allow-list; banned phrase tests | Customer output states or implies an item is safe for a disclosed allergy or health constraint. |
| 10 | INV-SAFETY-003 | Safety disclosure must propagate to kitchen tickets and structured order evidence. | SAFETY | `safety_disclosures` records; committer validator; kitchen ticket tests | A committed order with a safety disclosure lacks a kitchen-visible safety note. |
| 11 | INV-RELIABILITY-002 | No stale AI message may be sent after human takeover. | RELIABILITY | Ownership generation fencing; outbox ownership check; takeover race tests | Outbox dispatch sends an AI response whose ownership generation is older than the current human-owned thread. |
| 12 | INV-RELIABILITY-003 | No duplicate committed order may result from retries, duplicate webhooks, or confirm button replays. | RELIABILITY | Inbox/outbox idempotency keys; quote commit transaction; duplicate webhook tests | The same confirmed episode creates more than one order or emits more than one commit side effect. |
| 13 | INV-RELIABILITY-004 | At-least-once ingress must be paired with idempotent processing. | RELIABILITY | `channel_inbox` unique message keys; state-machine tests | Retried webhooks double-apply cart mutations, duplicate confirmations, or skip durable inbox recording. |
| 14 | INV-PRIVACY-002 | V1 memory is explicit-only. | PRIVACY | Memory writer validator; gold-set labels; privacy tests | Inferred preference, inferred allergy, inferred address, or inferred order habit is stored as memory. |
| 15 | INV-SAFETY-004 | Deterministic safety positives override model suggestions. | SAFETY | Safety detector; semantic validator; decision-kernel tests | The model suppresses, weakens, or reverses a positive allergy/health detector result. |
